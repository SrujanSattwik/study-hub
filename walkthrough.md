## 1. Executive Summary

Phase 4 transforms **KnowNook AI Assistant** from a traditional request-response model into a high-performance, real-time streaming assistant similar to ChatGPT, Claude, and Gemini.

Responses are streamed token-by-token using **Server-Sent Events (SSE)** directly to the client as they are generated by Gemini. This eliminates user wait times for long responses while ensuring zero redundant database operations, zero memory leaks, and seamless reuse of all context, prompt-building, and persistence layers built in earlier phases.

```
        ├─► 3. MemoryManager.package() (Sliding window + keyword relevance ranking)
        ├─► 4. PromptBuilder.build() (Assemble persona, context & history into prompt)
        │
        ├─► 5. Initialize SseEmitter (backend/src/ai/sse-emitter.ts)
        │        ├── Set Headers: text/event-stream, Connection: keep-alive
        │        ├── Start Heartbeat Interval (20s)
        │        └── Emit: 'conversation_started' & 'metadata'
        │
        ├─► 6. GeminiClient.generateStream() (backend/src/ai/gemini-client.ts)
        │        └── Consumes Gemini stream via chunked HTTP stream
        │
        ├─► 7. Token Parser & SSE Event Emission
        │        ├── Token accumulated in memory buffer (string[])
        │        └── Emit: 'token' { text, index }  (immediate TCP flush)
        │
        ├─► 8. Client Disconnect / Abort Monitoring
        │        └── Connection closed? → AbortController.abort() → Emit 'aborted'
        │
        ├─► 9. Post-Stream Processing & Persistence (Single DB Operation)
        │        ├── ResponseProcessor.process() (Sanitize output, detect math/code blocks)
        │        ├── Create User Message (aiMessageRepository.create)
        │        ├── Create Assistant Message (aiMessageRepository.create)
        │        ├── Increment Conversation Stats & Record Usage (aiUsageRepository)
        │        └── Emit: 'completed' & 'done'
        │
        └─► 10. Async Summarization Check
                 └── (If message count >= 30, background task updates summary)
```

## 4. Event Specification

All stream events conform strictly to the W3C Server-Sent Events specification:

```http
id: <event_number>
event: <event_type>
data: <json_formatted_payload>

```

### Event Inventory

| Event Name | Purpose | Example Payload |
|:---|:---|:---|
| `conversation_started` | Signals that connection is established and processing has begun | `{"conversationId":"8b1f23a4-..."}` |
| `metadata` | Shares initial model & estimated prompt token counts | `{"conversationId":"...","model":"gemini-2.0-flash","estimatedPromptTokens":342}` |
| `thinking` | Indicates AI reasoning or context preparation status | `{"status":"Generating response..."}` |
| `token` | Incremental chunk of output text delivered immediately | `{"text":"Quantum","index":0}` |
| `heartbeat` | Periodic ping every 20s to prevent proxy/firewall timeouts | `{"ts":1772134592000}` |
| `completed` | Fired after generation completes and messages are saved | `{"userMessageId":"...","assistantMessageId":"...","answer":"...","promptTokens":342,"completionTokens":180,"totalTokens":522,"generationTimeMs":1420,"model":"gemini-2.0-flash","finishReason":"STOP"}` |
| `done` | Indicates end of stream; client should close connection | `{"conversationId":"8b1f23a4-..."}` |
| `aborted` | Fired when client disconnects or abort signal is received | `{"conversationId":"...","reason":"client_disconnect"}` |
| `error` | Sent if an unhandled exception or provider failure occurs | `{"code":"STREAM_ERROR","message":"Gemini stream error: Quota exceeded"}` |

## 5. Abort Strategy & Cancellation

1. **AbortController Binding:** Every stream request instantiates a isolated `AbortController` passed to `GeminiClient.generateStream()`.
2. **Disconnect Listener:** Express response fires `res.on('close')`. If stream is in progress, `abortController.abort()` triggers immediately.
3. **HTTP Stream Destruction:** Axios stream connection to Gemini is explicitly destroyed (`stream.destroy()`).
4. **Loop Termination:** Generator loop checks `abortController.signal.aborted` before emitting each chunk and exits immediately if aborted.
5. **Resource Cleanup:** Timers (heartbeat, timeout) are cleared in the `finally` block via `SseEmitter.close()`.

---

## 6. Performance & Memory Strategy

* **In-Memory Token Buffering:** Streamed tokens are accumulated in an array of strings (`tokenBuffer: string[]`). No per-token database writes are performed during active streaming.
* **Single Batch Persistence:** Full database record creation (user message, assistant message, statistics increment, and token usage) occurs once in a single batch post-stream completion.
* **TCP Flush Optimization:** `res.flush()` is called explicitly after every token emission (with `X-Accel-Buffering: no` header for Nginx compatibility) ensuring sub-millisecond token delivery latency.
* **Zero Timer Leakage:** Heartbeat and hard timeout timers are strictly tracked and cleared upon stream completion, abort, or failure.

---

## 7. Security & Authorization

* **JWT Authentication:** Route protected by `authenticateToken` middleware.
* **Conversation Ownership Verification:** Requesting user's ID is cross-checked against conversation records (`findFullById(id, userId)`). Unauthorized access yields an error event and immediate stream closure.
* **Output Sanitization:** `ResponseProcessor` filters output against prompt injection patterns and malicious constructs before persisting to DB.
